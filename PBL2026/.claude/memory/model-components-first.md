Owner, 2026-10-12: *"from now anytime we need a component in the lecture, we will have to model it first this way the lecture
also helps us to build libraries enough to push to the server"*; and *"This psu is what we will keep now. when we need any
other capabilities we will model it intentionally"*.

**Why:** each lecture then leaves behind reusable, validated components (the server's library), instead of one-off
drawings; one model per real part keeps every lecture and bench consistent.

**How to apply:** before drawing any instrument or part in a lecture card, check whether it exists as a component
(bench-work/components/); if not, model it first (brief, manifest, class, 3D model, editor checks, golden cases, stills),
then use it in the lecture. Never fork a second version of an existing component for one lecture: one bench supply
(`exsight.supply.sw3005`); every lecture supply is being replaced with it. A new capability = a new component, on purpose.
Related: [[component-standard]], [[component-editor]], [[reuse-done-scenes]].
