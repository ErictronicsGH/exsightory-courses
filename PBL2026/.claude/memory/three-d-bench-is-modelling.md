Owner, 2026-10-08: *"3D bench is not for animations its for modelling. So research on what you are
creating rather goes to an Animation Bench."* Said when the eye-to-brain sequence (D1·010 card 3)
was being prototyped as a Model Bench tour.

**Why:** the 3D Bench (M24) shows built models (views, explode, isolate, callouts). A process that
unfolds in time, with stops, keyed points and overlays, is the Animation Bench's job (M62: play,
step, scrub, stops, keyed points, overlays, Blender import, light authoring).

**One bench for 2D and 3D** (owner, same day: *"one bench for 2D and 3D, go with your proposals"*).
The Animation Bench plays imported 3D and 2D clips and authored 2D process animations, using the
Draw Bench's motion vocabulary. The test for a card: a process moving through stages → Animation
Bench; a picture built up step by step → Draw Bench. Six course cards moved on that test (list in
`bench-work/animation-bench-capabilities.md` §9).

**Any animation library, never CAD** (owner, same day): *"this animation bench will contain things done
with say threejs or manim or any animation library. this is not where things like step files are worked
on. step files and CAD are handled at 3D Bench."* So the Animation Bench's sources are code run live
(three.js, under the C78 contract: a pure function of stop and progress), rendered video with section
markers (Manim and the like), and GLB/Lottie/SVG clips; STEP/CAD files are refused there.

**How to apply:** when a card needs motion through stages (the eye, a phasor turning, SAR's search,
a sample-and-hold cycle), target the Animation Bench in the spec. A Model or Draw stand-in for
Saturday is named as a stand-in, never as the target, and the 3D Bench is not proposed for animated
anatomy or processes at all: it is for CAD models. Related: [[research-before-bench-features]].
